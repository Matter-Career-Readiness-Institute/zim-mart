# ZimCart Hackathon Rules

## Team workflow

- Communicate with teammates before editing shared files; agree on ownership and coordinate changes to shared app state or project configuration.
- Each issue should describe the reproduction steps and the expected behavior.
- Develop fixes on branches and keep commits focused, with meaningful messages.
- Pull requests must explain the bug, the fix, and how the change was tested.
- Review a teammate’s change before merging it.
- Prioritize a working core shopping journey over cosmetic improvements.
- Share progress and blockers through your team’s agreed remote communication channel.
- Do not disable a feature or delete a failing check just to hide a defect. Explain and test the correction.

## Required demonstration

Browse products → open a product → add it to the cart → change quantity → checkout → place an order → see confirmation. Judging prioritizes a reliable core journey over fixing every issue.

## Scoring (100 points)

| Area | Points |
| --- | ---: |
| Core MVP functionality | 40 |
| Debugging quality and correctness | 20 |
| GitHub workflow and code review | 15 |
| Remote communication and collaboration | 15 |
| Testing and final demonstration | 10 |

Clear diagnosis and tested fixes earn credit. Line count does not. Deleting checks or disabling features to hide a defect does not earn debugging credit.
